# קטלוג מחשבי Dell - כלי סינון ובקשת הצעת מחיר בוואטסאפ

כלי עצמאי (לא תלוי בוורדפרס) שמאפשר ללקוחות לסנן מתוך קטלוג מחשבי ה-Dell
שמשווקים דרך הספק CMS (cms.co.il), ולשלוח בקשת הצעת מחיר מוכנה בוואטסאפ
ישירות מהמכשיר שלהם.

הפרויקט מורכב משני חלקים:

1. **סקריפט סקרייפינג** (`scraper/scrape.js`) - אוסף את כל מוצרי ה-Dell
   מאתר CMS וכותב אותם ל-`site/data/products.json`.
2. **אתר סטטי** (`site/`) - HTML/CSS/JS פשוט (בלי React, בלי בילד),
   שקורא את `products.json` ומציג ממשק סינון וחיפוש עם כפתורי וואטסאפ.

---

## התקנה ראשונית

צריך [Node.js](https://nodejs.org) גרסה 18 ומעלה מותקן במחשב. לבדוק עם:

```bash
node --version
```

לאחר מכן, בתוך תיקיית הפרויקט (`dell-catalog-app`), מתקינים את התלויות
(פעם אחת בלבד, או כשעוברים למחשב חדש):

```bash
npm install
```

## איך מריצים את הסקרייפר (עדכון הקטלוג)

בכל פעם שרוצים לרענן את רשימת המוצרים (מוצרים חדשים, שינויי מלאי וכו'):

```bash
npm run scrape
```

מה קורה בפועל:

- הסקריפט עובר על **כל הקטגוריות המוגדרות** (כרגע: מחשבים ניידים, מסכי
  מחשב, מחשבים נייחים ומחשבי All In One - ר' "הוספת קטגוריה חדשה" למטה)
  ובכל אחת על כל העמודים באתר cms.co.il (מזהה אוטומטית כמה עמודים יש).
- בין כל בקשה לעמוד הבא יש המתנה של 1-2 שניות, כדי לא להעמיס על השרת.
- התוצאה נכתבת ל-`site/data/products.json`, קובץ אחד עם כל המוצרים מכל
  הקטגוריות (לכל מוצר יש שדה `category`).
- **אין מחירים בקובץ** - האתר של הספק לא חושף מחירים בלי התחברות, ולכן
  זה לא נאסף ולא אמור להופיע.

### בקרת תקינות (safety check)

הבדיקה מתבצעת **בנפרד לכל קטגוריה**. אם באיזושהי קטגוריה מספר המוצרים
שנאספו קטן משמעותית (פחות מ-90%) ממה שהיה בקובץ הקודם, הסקריפט **לא
מעדכן את הקטגוריה הזו** (הנתונים הישנים שלה נשארים כמו שהיו) - שאר
הקטגוריות כן מתעדכנות כרגיל. הוא ידפיס אזהרה בקונסול, וישמור את התוצאה
שכן נאספה לבדיקה ידנית בקובץ `site/data/products.rejected.json` (מערך
לפי קטגוריה שנכשלה), כדי שתוכלו לבדוק מה קרה (למשל שהאתר של הספק שינה
את מבנה העמוד של הקטגוריה הזו).

---

## הוספת קטגוריה חדשה

הקטגוריות מוגדרות במערך `CATEGORIES` בתחילת `scraper/scrape.js`. כדי
להוסיף קטגוריה (למשל "מחשבים נייחים" או "מחשבי All In One"):

1. מוצאים את כתובת הקטגוריה המתאימה באתר cms.co.il (מסוננת ל-Dell בלבד,
   כמו `.../product-category/<שם-קטגוריה>/brand-dell/`).
2. בודקים איך נראית שורת המפרט הקצרה של מוצרים בקטגוריה הזו (מבנה
   ה-`| `-מופרד יכול להיות שונה לגמרי ממחשבים ניידים/מסכים).
3. כותבים פונקציית `parseXxxAttributes` שמפרקת אותה לשדות מובנים (בדומה
   ל-`parseLaptopAttributes`/`parseMonitorAttributes` הקיימות).
4. מוסיפים ערך חדש למערך `CATEGORIES` עם `id`, `label` (השם שיוצג בטאב
   באתר), `url` ו-`parseAttributes`.
5. באתר עצמו (`site/app.js`), מוסיפים ל-`CATEGORY_CONFIG` את שדות הסינון
   הרלוונטיים לקטגוריה (אילו checkbox-ים להציג) ואת אופן בניית שורת
   המפרט להודעת הוואטסאפ.

לאחר מכן `npm run scrape` יאסוף גם את הקטגוריה החדשה, והטאב שלה יופיע
באתר אוטומטית (טאבים מוצגים רק לקטגוריות שיש בהן בפועל מוצרים בנתונים).

## איך מעדכנים את "המוצרים המומלצים"

בקובץ `site/data/recommended-skus.json` יש רשימה פשוטה של מק"טים (SKU)
שמסומנים בתג "מומלץ" בכרטיס המוצר. אפשר לערוך את הקובץ ישירות בכל עורך
טקסט (גם Notepad):

```json
["LT-RD33-16991", "AL-RD33-16656"]
```

- אפשר לשים עד 20 מק"טים (או כמה שרוצים - זו רק המלצה).
- את המק"ט של כל מוצר אפשר לראות בכרטיס שלו באתר, או בקובץ `products.json`.
- שינוי בקובץ הזה לא דורש הרצה מחדש של הסקרייפר - רק לרענן את דף האתר.

## עדכון באנר הכותרת

בתצוגת דסקטופ (מ-900px רוחב ומעלה) הכותרת מציגה תמונת רקע רחבה
(`site/images/header-banner.jpg`) עם המלל של האתר (לא של הספק) מעליה.
מתחת למלל שלנו יש "וילון" כהה ורך שמכסה את הטקסט המקורי שהיה צרוב בתמונה
של הספק - זו לא הסרה מושלמת ברמת פיקסל (אין לנו כלים לזה), אלא כיסוי
שנראה טוב בגודל תצוגה רגיל.

אם מקבלים באנר קמפיין חדש מהספק ורוצים להשתמש בו:

```bash
npm run build:banner -- "הנתיב לקובץ התמונה החדש"
```

זה כותב מחדש את `site/images/header-banner.jpg`. יכול להיות שיהיה צריך
לכוון את מיקום ה"וילון" (המשתנים `rectX`/`rectW`/`rectY`/`rectH` בתחילת
`scraper/build-header-banner.js`) כדי שיתאים למיקום המלל בבאנר החדש -
פשוט מריצים, בודקים את התוצאה, ומכווננים לפי הצורך.

במובייל (מתחת ל-900px) הכותרת נשארת מלל פשוט על רקע כחול אחיד בלי
תמונה, כי פורמט באנר רחב כזה לא מתאים למסך צר.

## איך מריצים את האתר לבדיקה מקומית

```bash
npm run serve
```

זה יפתח שרת מקומי (בכתובת שתוצג בטרמינל, בדרך כלל
`http://localhost:5173`) שמגיש את תיקיית `site`. אפשר גם פשוט לפתוח את
`site/index.html` ישירות בדפדפן, אבל שרת מקומי קטן עדיף כדי שהדפדפן יטען
את קובצי ה-JSON בלי בעיות הרשאות.

### מגבלה חשובה - הסקרייפר לא יכול לרוץ מהענן

ניסינו להריץ את `npm run scrape` אוטומטית דרך GitHub Actions (בענן), אבל
אתר הספק (cms.co.il) מוגן ב-Cloudflare שחוסם בקשות שמגיעות מכתובות IP של
שירותי ענן/CI עם שגיאת HTTP 403 - זה לא קשור ל-User-Agent או לקצב
הבקשות, זו חסימה גורפת לפי מוצא הכתובת. בעברית: **הסקרייפינג בפועל חייב
לרוץ ממחשב "רגיל"** (למשל המחשב שלכם), לא משרת בענן.

לכן:
- ה-workflow ב-`.github/workflows/update-and-deploy.yml` מטפל **רק
  בפרסום** (Pages) בכל push - זה עובד מצוין כי הוא לא פונה ל-cms.co.il.
- את `npm run scrape` צריך להריץ ידנית (או דרך תזמון מקומי במחשב שלכם,
  ר' בהמשך) ואז לדחוף (`git push`) את התוצאה.

**זרימת עבודה מלאה לעדכון קטלוג:**

```bash
npm run scrape
git add site/data/products.json
git commit -m "עדכון קטלוג"
git push
```

### עדכון יומי אוטומטי - כבר מוגדר

יש משימה מתוזמנת ב-Windows Task Scheduler בשם `DellCatalogDailyUpdate`
שרצה כל יום ב-03:00 ומריצה את `scraper/daily-update.ps1` - הסקריפט הזה
מבצע `npm run scrape`, ואם הצליח (ולא נכשלה בדיקת התקינות של אף קטגוריה)
עושה `git add` + `commit` + `push` אוטומטית. הקטלוג באתר מתעדכן אז לבד
תוך דקה, בלי שצריך לגעת בכלום.

**חשוב להבין את המגבלה:** זה תלוי במחשב הזה (לא בענן) - אם המחשב כבוי או
לא מחובר לאינטרנט ב-03:00, פשוט לא תהיה עדכון באותו יום (Task Scheduler
לא "ירדוף" אחורה). הלוגים של כל ריצה נשמרים ב-`logs/daily-update-<תאריך>.log`
לצורך אבחון תקלות.

**להרצה ידנית מיידית** (לבדיקה, או כשלא רוצים לחכות ל-03:00):

```bash
npm run scrape && git add site/data/products.json && git commit -m "עדכון קטלוג" && git push
```

**לביטול המשימה המתוזמנת:**

```powershell
Unregister-ScheduledTask -TaskName "DellCatalogDailyUpdate" -Confirm:$false
```

**להקמה מחדש** (למשל אחרי שינוי שעה, או במחשב אחר):

```powershell
powershell -ExecutionPolicy Bypass -File scraper\register-daily-task.ps1
```

### המלצה: שילוב באתר הוורדפרס

יש שתי דרכים לשלב את הכלי הזה באתר הוורדפרס הקיים:

1. **אירוח חיצוני + קישור/כפתור בתפריט** - האתר הסטטי רץ בכתובת נפרדת
   (למשל `dell.yourdomain.co.il` או כתובת של Netlify/Vercel), ובתפריט
   הוורדפרס מוסיפים קישור רגיל אליה.
2. **הטמעה ב-iframe** - יוצרים עמוד וורדפרס רגיל ומטמיעים בו
   `<iframe>` שמצביע לאותה כתובת מתארחת.

**ההמלצה שלי: אפשרות 1 (קישור חיצוני), לא iframe.**

הסיבות:

- **מובייל** - רוב הגולשים מגיעים מהנייד, ו-iframe בתוך עמוד וורדפרס
  יוצר לרוב גלילה כפולה (גם של העמוד וגם של ה-iframe) וחוויית שימוש
  מסורבלת, בעיקר עם פאנל סינון שצריך גם הוא מקום לגלול.
- **קישורי וואטסאפ** - חלק מהדפדפנים/וובויוז בתוך אפליקציות (למשל
  פייסבוק, אינסטגרם) חוסמים או מתנהגים בצורה לא צפויה עם `wa.me` בתוך
  iframe מוטמע. קישור ישיר לעמוד עצמאי נפתח בדפדפן מלא, ושם `wa.me`
  עובד בלי בעיות.
- **תחזוקה** - עדכון האתר העצמאי (פרסום מחדש של `site/`) לא תלוי
  בגרסת וורדפרס, תוספים או תבנית, ולא יכול "לשבור" משהו אחר באתר.
- העלות/מורכבות של קישור רגיל מהתפריט זהה כמעט לגמרי ל-iframe - שתי
  האפשרויות דורשות רק להעלות דומיין/כתובת אחת.

כלומר: מפרסמים את `site/` באירוח סטטי (Netlify/Vercel/GitHub Pages),
ומוסיפים כפתור/קישור רגיל בתפריט הוורדפרס לכתובת הזו.
